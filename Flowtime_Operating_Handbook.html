Charter

The purpose, scope, and role-level targets that everything else in this handbook rolls up to.

Purpose

Track how time is actually spent across the three executive functions Arvind holds concurrently — CEO of OMNIVEX / NexTier, CISO-level security architecture work, and CTO-level technical delivery — against where it should be spent, and surface the gap.

Scope

All tracked work sessions logged in the Flowtime app, tagged to one of 34 categories rolling up into 3 roles (CEO, CISO, CTO). Out of scope: untracked/personal time, sessions shorter than 1 minute.

How to use this workbook

  1. Log sessions in the Flowtime HTML tracker — category and task chip picks come from the same 34-category / 1,700-subtask library referenced in this handbook.
  2. Weekly, transcribe session log entries into the WBS Tracker tab — Role and Category auto-fill from the Task dropdown; enter Est./Logged minutes and Status yourself.
  3. Check the Dashboard tab — role-mix % updates automatically from the Tracker tab via formula.
  4. Cells shaded pale yellow are the only ones meant for manual entry; everything else is a formula or fixed reference — leave it alone.

Prioritization methodology

Priority is set using PMI's Impact × Urgency Prioritization Matrix (a PMBOK decision-making tool), cross-referenced with the role objectives on the Charter tab. Each category is rated Impact and Urgency (High/Medium/Low); the two combine into a Priority per the standard 3×3 resolution: High Impact + High/Medium Urgency → High · Medium Impact + High Urgency → High · High Impact + Low Urgency → Medium · Medium Impact + Medium Urgency → Medium · Low Impact + High Urgency → Medium · everything else → Low.

This mirrors the MoSCoW tiering used in PMI-PBA requirements prioritization (High ≈ Must/Should-have, Medium ≈ Could-have, Low ≈ lowest-value). Priority values on the WBS Tracker are seeded from this matrix and remain manually editable per task — override any row where task-specific urgency differs from its category default.
